Greedy Algorithms

Dijkstra's Algorithm

Intro: Dijkstra’s algorithm finds the shortest path from a chosen node to all other nodes in a weighted graph.

Description: Dijkstra's algorithm picks the closest node to the chosen node that hasn't been visited yet. Then, it looks at the neighbors of that closest node and updates their distances if a shorter path was found. It's very similar to DFS and BFS but those don't work with weighted graphs.

History: Dijkstra's algorithm was made by computer scientist Edsger Dijkstra in 1956. He created it to show people that computers can solve complex problems, but specifically wanted to show it off on a ARMAC computer that was released in 1956. Fun fact: It took Dijkstra only 20 minutes to make his algorithm.

How to Solve:

  • Initialize all of the distances
  • Set source distance to 0
  • Use a priority queue
  • Repeatedly extract minimum node
  • Relax all neighboring edges

Time Complexity: O(E log V)

Space Complexity: O(V)

Kruskal's Algorithm

Intro: Kruskal’s algorithm finds the Minimum Spanning Tree (MST) of a graph.

Description: It sorts edges by weight and adds them to the MST if they do not form a cycle. A MST is a subset of edges that connects all vertices in the graph with the minimum possible total edge weight

History: Kruskal's algorithm was proposed by Joseph Kruskal in 1956 as a solution to the minimum spanning tree problem.

Use Case: Used in network design such as creating the most cost-effective road, or an electrical grid.

How to Solve:

  • Sort edges by weight
  • Initialize disjoint set
  • Add smallest edge that doesn't create a cycle
  • Repeat until V-1 edges selected

Time Complexity: O(E log E)

Space Complexity: O(V)

Why is it Greedy? Kruskal's algorithm is a greedy algorithm because it always selects the smallest edge that doesn't create a cycle at each step.

Divide & Conquer

Merge Sort

Intro: Merge sort is a recursive sorting algorithm, it splits arrays and lists into halves as many times as necessary and sorts them back together.

Description: The array is divided until subarrays of size one remain. After the array is fully broken down, the algorithm combines the sub array back together but in sorted order.

History: Merge sort was invented by John von Neumann in 1945. He developed it to sort large datasets on old computers.

Use Case: Used in siorting large datasets for stable implementations.

How to Solve:

  • Divide array into two halves
  • Recursively sort each half
  • Merge the sorted halves

Time Complexity: O(n log n)

Space Complexity: O(n)

Why is it Dividing and Conquering?Merge sort is considered a divide and conquer algorithm because it divides the problem into smaller problems, solves them recursively, and then conquers them.

Binary Search

Intro: Binary search is a efficient algorithm that searches a sorted array for a chosen element. Binary search cuts the array/list in half continuosly until it finds its element.

Description: The algorithm works by repeatedly dividing the array in half. Depending on if the target is higher, lower, or equal to the middle element, the algorithm divides either the right half or the left half. Unless the target was in the middle.

History: Binary search was first created by John Mauchly in 1946. It was developed as a way to quickly search through sorted data on early computers. Fun fact: Binary search is a very popular algorithm, nearly every programming language as a built-in library function for binary search.

Use Case: Used in searching sorted arrays, databases, search engines, and more.

How to Solve:

  • Find middle index
  • Compare with target
  • Search left or right half
  • Repeat until found

Time Complexity: O(log n)

Space Complexity: O(1)

Why is it Dividing and Conquering? The reason binary search is a divide-and-conquer algorithm is that it divides the list in half, searches for the target in half of it, and continues this process until it finds the target.

Dynamic Programming

Fibonacci

Intro:The Fibonacci sequence is a classic example that is given in the context of dynamic programming and recursion in computer science. The sequence is obtained by summing the previous two numbers.

Description:The Fibonacci sequence starts with a 0 and 1. Each Number after the 0 and 1 is the sum of the two last numbers.

History: Fun fact, The Fibonacci sequence was actually first mentioned in a book by Leonardo of Pisa back in 1202. The book described the growth rate of rabbits since each rabbit produces a pair in the next generation.

Use Case: Used in algorithm design, mathematics, and nature patterns like rabbits offsprings.

How to Solve:

  • Start with the base case
  • Build new Fibonacci number using the previous two numbers

Time Complexity: O(n)

Space Complexity: O(n)

Knapsack Problem

Intro: The Knapsack problem's goal is to solve the question of how to optimize the selection of a set of items that can be carried in a knapsack while still maximizing the overall value. The weights and values of the items in the knapsack are very important because it is necessary to maximize the value of all of the items in total without it being too heavy.

Description:The most commonly discussed one is the 0/1 Knapsack Problem. In the 0/1 Knapsack Problem, items can be either taken or left out. The problem becomes challenging because checking all item combinations is computationally expensive. The problem is usually solved using a technique known as dynamic programming. In the Knapsack Problem, a table stores the maximum value achievable with a given number of items. The idea is to break the problem into smaller subproblems. The optimal solution to the problem is then obtained by combining the optimal solutions to the smaller subproblems.

History:.

How to Solve:

  • Create DP table
  • Iterate through items
  • Choose max between including or excluding item

Time Complexity: O(nW)

Space Complexity: O(nW)

Why is it Dynamic Programming?The knapsack problem is considered a dynamic programming problem because it divides the problem into smaller subproblems, solves each problem once, and then stores the results.

NP Heuristic

Traveling Salesman Heuristic

Intro: The Traveling Salesman Problem (TSP) involves finding the shortest route visiting all cities once.

Description: Because it is NP-hard, heuristics like nearest neighbors give potential solutions that are close to optimal.

How to Solve:

  • Start at a city
  • Choose nearest unvisited city
  • Repeat until all cities visited

Time Complexity: O(n²)

Space Complexity: O(n)

GitHub Repo

Why is it NP Heuristic? The nearest neighbor method for the Traveling Salesman Problem is a fast method to find a good path, though not necessarily the optimal path because there is no definitive way to guarantee the best path. So the method is used because the problem is very difficult (NP-hard) to solve optimally.

Interval Scheduling

Interval Scheduling Algorithm

Intro: Interval scheduling selects the maximum number of non-overlapping intervals. The goal would be to schedule the most amount of compatible events without conflicts.

Description: It is a greedy algorithm that sorts intervals by finishing time.

History: Interval scheduling was "created" in the 1950 when workers needed help to figure out tanker scheduling problems.

Use Cases: Assigning jobs, scheduling meetings/sharing classrooms, allocating resources and more.

How to Solve:

  • Sort intervals by finish time
  • Select first interval
  • Pick next interval that starts after last finish

Time Complexity: O(n log n)

Space Complexity: O(1)
